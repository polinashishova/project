# Экспертная оценка безопасности

## Область сканирования

В рамках практической работы было выполнено сканирование локального
авторизованного ресурса `127.0.0.1`.

Для анализа использовались следующие инструменты:

- Nmap — определение открытых портов, сервисов и их версий;
- Masscan — быстрое обнаружение открытых портов;
- Nikto — проверка веб-сервисов на типовые проблемы безопасности.

Сканирование выполнялось только в отношении собственного локального
ресурса. Инфраструктура GitHub и сторонние информационные системы
не сканировались.

## Результаты Nmap

### 1. Открытый порт 631/tcp

Nmap обнаружил открытый порт `631/tcp`. На порту был определён сервис
CUPS версии 2.4.

**Категория:** открытый порт / сервис.

**Уровень:** информационный.

**Экспертная оценка:** наличие открытого порта само по себе не
свидетельствует об уязвимости. Необходимо определить, требуется ли
данный сервис на исследуемой системе и должен ли он быть доступен
по сети.

**Рекомендация:** если сервис CUPS не используется, рекомендуется
отключить его. Если сервис необходим, следует ограничить сетевой
доступ к нему и использовать актуальную версию программного
обеспечения.

### 2. Открытый порт 8000/tcp

Nmap обнаружил открытый порт `8000/tcp`. На порту был определён
HTTP-сервис `SimpleHTTPServer 0.6`.

**Категория:** открытый порт / веб-сервис.

**Уровень:** информационный.

**Экспертная оценка:** открытый HTTP-сервис требует проверки
необходимости его использования и содержимого, доступного через
него. Использование простого HTTP-сервера в рабочей среде может
создавать дополнительные риски при публикации чувствительных
файлов.

**Рекомендация:** если сервис используется только для локальной
разработки или тестирования, рекомендуется ограничить его
доступ только локальным интерфейсом. Не следует размещать через
него конфиденциальные данные.

## Результаты Masscan

### 3. Открытый порт 445/tcp

Masscan обнаружил открытый TCP-порт `445`.

**Категория:** открытый порт.

**Уровень:** информационный.

**Экспертная оценка:** порт 445 обычно используется сетевыми
службами Windows/SMB. Сам факт обнаружения открытого порта не
является доказательством уязвимости, однако требует проверки
работающего сервиса и необходимости его сетевой доступности.

**Рекомендация:** проверить, какой сервис использует порт 445,
и ограничить доступ к нему, если он не требуется.

### 4. Открытый порт 135/tcp

Masscan обнаружил открытый TCP-порт `135`.

**Категория:** открытый порт.

**Уровень:** информационный.

**Экспертная оценка:** порт 135 связан с сетевыми механизмами
Windows RPC. Необходимость его доступности следует оценивать
с учётом назначения системы и используемых сетевых сервисов.

**Рекомендация:** проверить назначение порта и ограничить доступ
к нему с использованием правил локального или сетевого
межсетевого экрана, если удалённый доступ не требуется.

## Результаты Nikto

В результате выполнения Nikto был сформирован HTML-отчёт для
исследуемой цели.

В отчёте отсутствуют дополнительные findings, которые можно было
бы классифицировать как обнаруженные веб-уязвимости или ошибки
конфигурации.

Таким образом, по результатам проведённого автоматического
сканирования Nikto дополнительные проблемы безопасности
не зафиксированы.

Отсутствие findings в отчёте Nikto не означает абсолютного
отсутствия уязвимостей. Оно означает только, что используемый
набор проверок Nikto не выявил соответствующих проблем.

## Общая оценка

По результатам проведённого сканирования были обнаружены
несколько открытых сетевых портов:

- `631/tcp` — CUPS;
- `8000/tcp` — SimpleHTTPServer;
- `445/tcp`;
- `135/tcp`.

Обнаруженные результаты классифицированы как информационные,
поскольку полученные данные сами по себе не подтверждают наличие
уязвимости.

Наибольшее внимание при дальнейшей проверке следует уделить
определению необходимости каждого открытого сервиса, ограничению
сетевого доступа и проверке актуальности используемого
программного обеспечения.

## Рекомендации

1. Проверить необходимость каждого обнаруженного открытого порта.
2. Отключить неиспользуемые сетевые сервисы.
3. Ограничить сетевой доступ к необходимым сервисам с помощью
   правил межсетевого экрана.
4. Не использовать простой HTTP-сервер для публикации
   конфиденциальных данных.
5. Проверять версии сетевых сервисов и своевременно устанавливать
   обновления безопасности.
6. Проводить повторное сканирование после изменения конфигурации.
7. Использовать результаты автоматических сканеров как основу
   для дальнейшей ручной проверки, а не как самостоятельное
   подтверждение наличия уязвимости.

## Правовое соответствие

Сканирование проводилось только в отношении локального
авторизованного ресурса `127.0.0.1`.

Инфраструктура GitHub и сторонние информационные системы
не подвергались сканированию.

Полученные результаты используются исключительно в учебных
целях в рамках практической работы по анализу безопасности.
